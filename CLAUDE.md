# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Snapr: a Windows-only tray screenshot app (fullscreen, window, area capture with global hotkeys and a preview toast).
Tauri 2 backend in `src-tauri/`, React 19 + TypeScript + Tailwind v4 + shadcn (base-ui, "base-vega") settings UI in `src/`.
It is a port of the v1 winit app at `V:\source\repos\snapr` (commit `8ac4086`).

## Commands

Use **bun**, never npm/pnpm.

- `bun run tauri dev`: run the app (starts Vite on port 1420, strict)
- `bun run tauri build`: release bundle (NSIS only; `createUpdaterArtifacts` needs `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` set, or the build fails at signing)
- Release: bump the version in `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` and `package.json`, commit and push, then run the Release workflow by hand (Actions tab or `gh workflow run release.yml [-f notes=...]`; `workflow_dispatch` only, no tag trigger). `.github/workflows/release.yml` checks the three versions match and that `v<version>` is not already on `snapr-releases`, builds and signs on `windows-latest` and publishes the installer, `.sig` and `latest.json` to the public `quanvudev/snapr-releases` (secrets `RELEASES_TOKEN`, `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`). The source repo stays private.
- `bun run release`: local alternative to the workflow. Requires the three versions to match and a clean tree, refuses a version already on `snapr-releases`, signs with `~/.tauri/snapr.key` + `snapr.key.password` (or the env vars), builds, writes `latest.json` and creates the release with `gh` targeting `main`. It does not tag the source repo; do not also run the workflow for the same version (it refuses an existing release anyway).
- `/release [major|minor|patch|x.y.z] [--yes]` (`.claude/skills/release/`): reads the commits and the diff (openspec deltas first, then config, tray, commands, i18n and settings UI) since the last `snapr-releases` release, decides the semver bump from user-visible impact, prepends a `CHANGELOG.md` entry and uses it as the release notes, asks to confirm unless `--yes`, bumps the three versions and `Cargo.lock`, commits `chore: release v<version>` with `CHANGELOG.md`, pushes master (no tag) and runs `bun run release <notes>`.
- `bunx tsc --noEmit`: type-check the frontend
- `cargo clippy` (in `src-tauri/`): lint the backend
- `bunx --bun shadcn@latest add <component>`: add a shadcn component to `src/components/ui/`

There are no tests.

## Architecture

The app runs **two event loops in one process**:

- **Tauri (tao) on the main thread** owns the tray, global hotkeys (`tauri-plugin-global-shortcut`), the settings webview window (label `main`) and config state.
- **A winit event loop on a dedicated thread** (`spawn_capture` in `src-tauri/src/lib.rs`, built `with_any_thread(true)`) owns the native capture overlay, the preview toast and screen pins.
  - The capture overlay (window/area/text/record pickers) covers all monitors (`overlay::desktop()` stitches every monitor into one frame over the union rect), while fullscreen capture, the toast and the record-picker desktop fallback stay on the cursor's monitor.
  - This split exists because Tauri window events carry no mouse or keyboard input, which the overlay needs.
  - Hotkey handlers send `Action` (Fullscreen / Pick(Window) / Pick(Area) / Text / Record / Draw / Ring) through an `EventLoopProxy` that is stored in managed `State`. There are seven hotkey slots (`Hotkeys::combos()` is `[String; SLOTS]` with `SLOTS = 7`, order fullscreen, window, area, text, record, draw, ring). `Hotkeys.mode` is `fixed` (default, the original model: the shared `modifiers` prefix plus a bare key per slot, `combos()` prefixes unless the key has a `+`, is a mouse binding or is empty) or `manual` (`Hotkeys.manual`, one full combo per slot, no prefix; stored separately so switching modes never overwrites either set, and the first switch to manual seeds it from the resolved fixed combos in `ModeRow`). A config without `mode` loads as fixed unchanged. While a row records a combo the frontend calls `set_listening(true)`, which unregisters every global shortcut and the mouse hook so an already-mapped combo is recorded instead of firing; `set_listening(false)` (and `api.hide`, and a window `CloseRequested`) calls `apply()` to restore them. `text`, `draw` and `ring` have field-level `#[serde(default)]` so an older config without them stays unbound (empty) instead of colliding with an existing binding. `config::skipped(i, combos, text_active)` is the one place that skips an inactive or empty text slot and an empty draw or ring slot; `apply()` and `settings::rows` both use it.
  - Recording: `Action::Record` opens the window picker with `Snap.mode = Mode::Record`. The picked hwnd goes to `Recorder::start` (`recorder.rs`, `windows-capture`: WGC + H.264 MP4) as `Target::Window` instead of the save worker. `Overlay::open` takes a `record` flag (true only for `Mode::Record`): a left press then only remembers the start point, a move of more than 4 px on either axis switches the picker to drawing an area rectangle, and the release returns `Shot::Region { rect, start, hwnd }` (screen coordinates, `hwnd` = window under the start). A release without that movement is a click: `Snap::window_event` intercepts a left release with `Overlay::clicked()` whose `Overlay::hovered()` is `None` or a desktop window (`Progman`/`WorkerW`) and records the monitor under the cursor as `Target::Monitor`; otherwise the overlay picks the window as before. `region_target` clips the region to the monitor under the drag start (`frame::monitor_at`), rounds the size down to even and builds `Target::Area { monitor, rect }` (rect relative to the monitor, physical px); under 16x16 it falls back to a click at the start (window, or the monitor on the desktop). The window screenshot picker passes `record = false`, so it ignores drags. `Target::Area` runs a monitor WGC session, builds the encoder at the area size and, for each sent frame only, crops it with `buffer_crop` and sends it with `send_frame_buffer` (window and monitor targets keep `send_frame`); `keep()` uses the same crop. While an area recording runs, `Snap.frame` holds a `frame::Frame`: a click-through (`WS_EX_TRANSPARENT`), topmost, non-activating, `WDA_EXCLUDEFROMCAPTURE` layered window drawing a 2 px accent border just outside the area, dropped on `Recorded` / `RecordFailed`. Countdown: every record pick goes through `Snap::begin(target, bounds, area)`; with `record_countdown` on it hides pins (recording reason), opens a `frame::Digit` (layered, click-through, non-activating, excluded from capture, 160 logical px, centered on the target and clamped to its monitor), enables Stop and stores `Snap.countdown`; `tick_countdown` (from `about_to_wait`, deadline in the `WaitUntil` min) steps 3, 2, 1 once a second, then drops the digit and starts `record` 50 ms later, so the file name is the real start time. Cancel paths: `Action::Record` while `Snap.countdown` is `Some` cancels instead of opening the picker (the hotkey and the ring Record wedge reach it through `trigger`), and the tray Stop item sends `Action::CancelCountdown` when `stop_recording` found no recorder; cancel and a failed start show pins again, disable Stop and restore the tooltip. Esc does not cancel (the digit window never takes focus). The recorder lives in `State.recording` (`Mutex<Option<Recorder>>`) so the main thread can stop it: the record hotkey (while recording), the tray "Stop recording" item (`State.stop`) and Quit take it out of the mutex, then call `stop()`, which finalizes synchronously. On stop or window close the handler finishes the file and sends `Action::Recorded`, which clears `State.recording`, restores the tooltip and opens the toast. Never hold `State.recording` while calling `stop()`.
  - The loop never encodes: it hands each capture to a background save worker thread as a `Job` (`Save(Shot)` / `Text(Shot)`) (`std::sync::mpsc`, started in `spawn_capture`). When `padding.enabled`, the worker first pads the image with `capture::pad` (transparent, or the `padding.image` background scaled to cover; with no image and `padding.wallpaper` on, the current desktop wallpaper from `capture::wallpaper()` (`SPI_GETDESKWALLPAPER`, empty for a solid colour, which pads transparently) is used instead; backgrounds decode with a content-guessed format, since the wallpaper is often the extensionless `TranscodedWallpaper`), so the file, clipboard and toast all get the padded image; a background load error pads transparently and is shown in the tooltip after `refresh`. The worker saves the PNG, reports back with `Action::Saved` (which opens the toast), then copies to the clipboard. It caches the decoded `padding.image` in a `BackgroundCache` keyed by path + modified time.
  - Text capture: `Action::Text` opens the area picker in `Mode::Text`; the worker (WinRT initialized MTA once) runs `read_text`: `ocr::qr` (`rqrr`, luma downscaled to 2000 px on the longer side, codes sorted top to bottom) first, and when any QR code decodes it copies them one per line and notifies "QR code copied" (or a count), otherwise `ocr::extract` with the selected engine; it copies with `arboard` regardless of `copy_to_clipboard`, and reports via `tauri-plugin-notification` from Rust (en/vi strings in `lib.rs`), never the toast. The text hotkey is registered only when `text_capture && State.ocr`; `State.ocr` caches `ocr::available()`, re-probed in `apply()` and in `show_settings()` (which re-applies when it changed). `settings::rows` skips an inactive or empty text slot (no error, no in_use, no duplicate). The pin Copy text button (`pin::Outcome::Text`, the pin's full-resolution image) sends the same `Job::Text`. The gallery does not touch the clipboard: the async `gallery_text` command decodes the photo on a `spawn_blocking` thread (WinRT MTA), runs `ocr::qr` and `ocr::extract` and returns `{ qr, text }` to the viewer's text pane; both are offered only while `State.ocr`, regardless of `text_capture`.
  - Draw capture: `Action::Draw` opens the area picker with `Overlay::open(.., draw = Some(Snap.style))` in `Mode::Shot` (`None` for every other picker). An area release enters an annotating phase (`Annotation { sketch, toolbar, hover, palette }`) instead of saving. The selection stays editable: eight handles (corners and edge midpoints; `HANDLE_HIT` 14 logical px hit zone, `HANDLE_SIZE` 8 drawn squares, hit before the toolbar and before drawing, matching resize cursors; state in `Annotation.adjust` / `space` / `label`) resize it live, and holding Space (not while a text box is open) and dragging inside it moves it; the rect is normalised (min 3x3, clamped to the frame) and `Sketch::reselect` re-crops the background from the frozen frame and translates shapes, undo / redo snapshots, the open text box and the drag so shapes keep their screen position (parts outside the final selection are clipped). Selection changes are not undoable. A `W × H` physical-px size label sits at the selection's top-left (above it, else inside), a `toolbar::tag` pill (shared with the tooltip), drawn in `overlay::draw` only, never in `finish()`. The toolbar is two rows: a fixed main row (the constant `MAIN_ROW`: rectangle, ellipse, arrow and text tools, Undo / Redo, Pin / Copy, Done / Cancel, same positions for every tool) and an options row for the active tool or selected shape, on the side of the main row away from the selection and hidden when empty. The toolbar is centred on the selection and re-placed after a resize or move ends. Rectangle and ellipse (drawn or selected) show an Outline only | Outline and fill icon pair (hollow square / filled tinted square, current one marked; `StrokeStyle.fill`, key F toggles; tooltips vi Chỉ viền / Viền và tô), an outline colour button (hollow ring in the colour), a fill colour button (filled square, `StrokeStyle.fill_colour`, default same as outline, picking one turns fill on) only in fill mode and thin / medium / thick widths (each button draws a bar of the real thickness); arrow shows the outline colour button and widths; text shows the text colour button (filled circle), size down / current size / size up, bold and italic. The toolbar has no text. There is no popup: a colour button click sets `Annotation.palette` and the options row is replaced by a palette row (that colour button marked current, a divider, 8 swatches; no Back or caption); clicking that button again, a swatch (applied first), Esc, a tool switch or any click elsewhere closes it. A filled shape is also hit and moved from its inside. Placement tries below the selection, then above it, then inside its top edge (by the combined height of both rows, so the options row appearing never flips the side), clamped to the selection's monitor rect (`desktop()` returns the monitor rects, relative to the overlay origin). Keys: R/C/A/T switch tools (not while a text box is open), `[` / `]` step the width (shape tools) or the text size, Ctrl+B / Ctrl+I toggle bold / italic with the text tool (also while typing), Ctrl+Z undoes, Ctrl+Y / Ctrl+Shift+Z redoes, Ctrl+C copies (not while a text box is open), Ctrl+P pins, Ctrl+S / Enter / ✓ Done saves, Esc / ✗ cancels. Undo and Redo are dimmed and ignored when unavailable: `overlay::enabled(sketch, button)` filters `hit` results. Holding Shift while dragging makes a square or circle (sized by the larger side) or snaps the arrow to 45°, live and on release. While a text box is open, typed text goes into it (Enter adds a newline, Backspace deletes, Esc commits it). With any tool, hovering a shape's outline (or a text shape's box) shows the Move cursor; a press there moves the topmost hit shape (live) and selects it, any other press draws and clears the selection. The selected shape gets a dashed accent box in `view()` only (never in `finish()`); Delete removes it; the toolbar then shows that shape's kind and style, and an option click or `[` `]` Ctrl+B Ctrl+I restyles it and becomes the current style. Escape closes an open palette first, then clears the selection, then commits an open text box, then cancels. Undo is a snapshot stack of `Vec<Shape>` pushed before every add, move (once per drag), delete and restyle; `Sketch.redo` holds the undone snapshots: `snapshot()` clears it, so a move snapshots lazily on its first real delta; Ctrl+Z discards an open text box first (leaving `redo` alone). Right-click is ignored while annotating. Done returns `Outcome::Save(Shot::Ready(..))` through the normal save worker. Copy returns `Outcome::Copy(RgbaImage)` handled in `lib.rs`: `capture::copy` on the capture thread, clipboard only (no file, padding or toast; errors in the tooltip). Pin returns `Outcome::Pin(RgbaImage)`: `Pins::add` after `show_capture`, no file or padding. Neither uses the save worker. `Snap.style` (`draw::Style`) keeps the chosen colours, width, size, bold and italic until snapr quits: `window_event` takes `Overlay::style()` back on save, copy, pin or cancel. It is never written to the config.
  - Action ring: `Action::Ring` opens `Ring` (`ring.rs`), a transparent per-pixel-alpha (`UpdateLayeredWindow`) native winit window centred on the cursor and clamped to its monitor, drawn with tiny-skia in the Logitech Actions Ring style: eight floating black round icon buttons (Segoe Fluent Icons) on a circle, a white label card beside each and a small centre x that cancels. One `WEDGES` table (label, vi label, glyph) drives layout and hit-testing; buttons and cards both pick. The settings ring page draws the same glyphs: `BUILTINS[id].glyph` and `GENERIC_APP_GLYPH` in `lib/ring.ts` mirror `WEDGES` and `APP_GLYPH` and render through `Glyph` (`ring-icon.tsx`, Segoe Fluent Icons with the MDL2 fallback); change both sides together. `Snap::open_ring` passes the wedges in display order (Fullscreen, Window, Area, Text, Record, Draw, Gallery, Settings), with Text only when `text_capture && State.ocr`, and the Record wedge reads Stop recording while `State.recording` is `Some`. The hotkey toggles it closed and is ignored while an overlay is open. Esc, a centre or outside click, losing focus and `ring.idle_close` seconds without input (default 5, 0 = never; no cursor move, key or click on the ring and no button hovered; read at open, picked from a Select on the ring page) cancel it. A pick drops the ring first, then `wedge_action` maps it after `RING_HIDE_DELAY` so the picker's frozen frame never contains the ring: capture wedges go through `trigger` (Record stops a running recording), Gallery and Settings call `show_settings`. The ring hotkey may also be a mouse button (`Mouse3` middle, `Mouse4` back, `Mouse5` forward, optional `Ctrl+`/`Alt+`/`Shift+`; never prefixed with the shared modifiers): `mouse.rs` runs a `WH_MOUSE_LL` hook thread that swallows the exactly-matching press and its release and sends `Action::Ring`; `apply()` binds the hook for a mouse ring combo (`config::is_mouse`) and the shortcut plugin otherwise, `settings::rows` skips needs-modifier and in-use for it, and only the ring row of the hotkey recorder accepts the mouse.
  - Screen pins: `Action::Pin(PathBuf)` (the toast Pin action or the `gallery_pin` command) decodes the file and `pin.rs` creates a frameless, always-on-top, non-activating layered window (`UpdateLayeredWindow`, per-pixel alpha; reuses `ring::bitmap` / `ring::present`) centred on the cursor and clamped to the work area, capped at about 250 logical px on the larger side (DPI-scaled) with smaller images at 1:1. A pin draws the image 1:1, drags with `SetCapture` / `GetCursorPos`, and shows a hover toolbar (Copy `E8C8`, Copy text `E8D2` only when `State.ocr` was true at `Pin::open`, Close `E711`, check flash `E73E` on Copy only); Copy and Copy text use the original full-resolution image, and the window's minimum size grows with the button count. `Pins` keeps independent `capture` and `recording` hide reasons: pins hide before `Overlay::open`, before `capture::fullscreen` and before `record(...)`, and reappear when the last reason clears, so a screenshot during a recording keeps them hidden; they are not `WDA_EXCLUDEFROMCAPTURE`, so other apps' screen shares see them. `Action::PinMany(Vec<PathBuf>)` creates one pin per path with a 24px cascade for the gallery's bulk Pin; `Pin::open` takes the placement offset. Pins are in-memory only and disappear on quit. The toast shows its Pin action only while hovered and only on screenshot toasts (`Toast::open` takes `pinnable`; `Action::Recorded` passes false).
  - The capture thread reads config from `State.cfg` (`RwLock`) and reports status and errors through the tray tooltip.

Backend modules:
- `capture.rs`, `overlay.rs` and `toast.rs` come from v1. `overlay.rs` and `toast.rs` re-apply their physical size and position after `create_window` (mixed-DPI fix), and the overlay spans all monitors.
  - Win32 capture uses `PrintWindow` + DWM bounds, with rounded corners added.
  - Saves a timestamped PNG and can also copy the image to the clipboard. `capture::unique_path(dir, ext)` gives the timestamp + `_N` name for both PNGs and recordings.
- `config.rs` holds the TOML config at `app_config_dir()/config.toml` (`%APPDATA%\com.quanvudev.snapr`).
  - The path is resolved in `setup` and stored in `State`.
  - `load` returns defaults without writing when the file is missing; only `save` creates it. A missing file means first run.
  - `parse_hotkey` maps `Win` → `Super`.
  - `record_countdown` (`#[serde(default)]`, off) turns the 3-second countdown on; it is read at pick time.
  - `update_check` (default true, so an older config loads with it on) turns the automatic update check on.
  - `record_fps` is read only through `Config::fps()`, which returns 60 for 60 and 30 for anything else; `recorder.rs` derives both the frame throttle and the encoder rate from it.
- `draw.rs`: `Tool` and the closed `Shape` enum with `render`, drawn by tiny-skia. Each shape keeps the `StrokeStyle { colour, width }` or `TextStyle { colour, size, bold, italic }` it was drawn with (`PALETTE`, `WIDTHS`, `SIZES`; defaults red, 4, 20 regular); an open text box uses the current `TextStyle`. Text goes through `ab_glyph` with `%WINDIR%\Fonts\segoeui.ttf` loaded lazily (the text tool is disabled if it fails); bold / italic / bold-italic (`segoeuib`, `segoeuii`, `segoeuiz`) are looked up by `(bold, italic)` and fall back to regular. `system_font(files)` is the shared loader, also used for the toolbar icon font. `Sketch` holds the editing state, a cached layer of committed shapes, `view()` for the live preview and `finish()` for the saved image, plus `reselect(frame, rect)` (re-crop and translate, see Draw capture) and the `history` / `redo` stacks with `can_undo()` / `can_redo()`.
- `toolbar.rs`: `Button` (tools, `Undo`, `Redo`, `Pin`, `Copy`, save (the Done ✓) and cancel, and the options: `Colour` and `FillColour` (the icon-only colour buttons), `Outline`, `Fill`, `Width(i)`, `Smaller`, `Larger`, `Bold`, `Italic`; `Swatch(i)` only in the palette row), `Palette` (`Stroke` / `Fill`, which colour the open palette row picks), `Toolbar::place(selection, monitor, scale, vi)` (centred, `main` and `options` rects), `hit(at, kind, fill, palette)` (does not know about disabled buttons; `tooltip` takes the palette too), `render(tool, kind, style, hover, palette, &dyn Fn(Button) -> bool)` returning `Vec<(&Pixmap, (i32, i32))>` (main row, then the options or palette row when non-empty; the active tool and current options marked; the closure dims disabled buttons), `tag(text, scale)` (the pill shared by tooltips and the size label), `tooltip` and `shortcut`. The rows are slot lists the constant `MAIN_ROW` and `options_row(kind, fill, palette)` (while `palette` is `Some`, the active colour button, a divider and 8 swatches instead) and laid out by `layout(rows, scale)`; the Outline only / Outline and fill pair is two icon buttons and nothing in the toolbar is text; the panel base (`paint_panel`) is repainted only when the row changes. Hovering a button shows a tooltip immediately (name plus shortcut, en/vi from `config.language` via `Overlay.vi`, Segoe UI 12 px, placed below the panel or above it near the monitor bottom, cached per button; none if the font is missing). Icons come from Segoe Fluent Icons (`SegoeIcons.ttf`, falling back to `segmdl2.ttf`) through `ab_glyph` outlines filled as tiny-skia paths; the arrow glyph is rotated 45°. With no icon font the buttons draw no icon.
- `frame.rs`: `monitor_at(point)` (HMONITOR, monitor rect, DPI scale), the area-recording `Frame` and the countdown `Digit` windows, both click-through, non-activating and excluded from capture, drawn through `ring::present`.
- `pin.rs`: the layered pin window and `Pins` collection: placement, 1:1 scaling, drag, hover Copy/Close, copy flash and the independent capture/recording hide reasons. Uses the ring's `bitmap` / `present` layered helpers.
- `ocr.rs` holds `qr()` (`rqrr`) and wraps `Windows.Media.Ocr` (`windows` 0.62, same version as `windows-capture` pulls in): `windows_available()` and the Windows path of `extract()` using the Windows profile languages, downscaling above `MaxImageDimension`.
  - OCR engine: `config.ocr_engine` (`windows` default, `paddle`) and `config.paddle_model` (`tiny` / `small` default / `medium`). `paddle::selected(app, cfg)` returns an `ocr::PaddleModel` only when the engine is paddle and that size is ready; `ocr::available(model)` is `model.is_some() || windows_available()` and `ocr::extract(img, model)` runs PaddleOCR when given a model (falling back to Windows OCR only if PaddleOCR errors), else Windows. `State.ocr` caches that combined availability (`ocr_available(app)` in `lib.rs`), so a ready Paddle model lights up text capture on a machine with no Windows OCR language. `read_text` and `gallery_text` resolve the model from `State.cfg`; `apply()` calls `paddle::unload_others` so only the selected size stays loaded.
  - `ocr/paddle.rs` is the PP-OCRv6 pipeline over `ort` (`=2.0.0-rc.15`, `load-dynamic`; every `ort` call lives there). The runtime is `ort::init_from(<paddle>/onnxruntime.dll)` once per process (an absolute path, because Windows 11 ships its own `System32\onnxruntime.dll`; the result, including an error, is kept in a `OnceLock`, and the DLL cannot be unloaded or deleted while the process runs). Detection mirrors Paddle's `DetResizeForTest` (min side 64, max side 4000, multiples of 32), BGR ImageNet normalization, a 4-neighbour flood fill over `prob > thresh`, a `box_thresh` mean filter and the DB unclip distance, axis-aligned only; recognition crops each box to height 48 (width 320..3200), batches of 8, greedy CTC with `dict.txt` plus a trailing space. Lines go through `ocr::rows`, the same row grouping as the Windows path. `ocr::ENGINE` caches one `(PaddleSize, Engine)`; `ocr::paddle_unload` drops it.
- `paddle.rs` is the PaddleOCR model store: a pinned table (`MODELS`: Hugging Face `PaddlePaddle/PP-OCRv6_<size>_{det,rec}_onnx` URLs at a fixed commit with SHA-256 and byte size, per-size `det_params` `(thresh, box_thresh, unclip_ratio)`, and the `onnxruntime` cp313 win_amd64 wheel on PyPI from which only `onnxruntime/capi/onnxruntime.dll` is extracted). Files live in `app_local_data_dir()/paddle/` (`onnxruntime.dll`, `<size>/det.onnx`, `rec.onnx`, `dict.txt`); `ready(app, size)` is those four files existing. Each file streams to `.part` with a SHA-256 + exact size check and is renamed only on success; `dict.txt` (the rec `inference.yml` `PostProcess.character_dict`, parsed with `yaml-rust2`) is written last; a failure or cancel removes the whole size folder. One download at a time in `State.download` (`Download { size, cancel, done, total }`) on its own thread; it emits `paddle-progress { size, done, total }` (throttled 100 ms), then runs `apply()` on the main thread and emits `paddle-done { size, error }` (`error: null` on cancel). Commands: `paddle_status` (`{ ready, bytes, downloading, runtime }`), `paddle_download(size)`, `paddle_cancel`, `paddle_delete(size)` (refuses the downloading size, unloads it, removes the folder, removes the DLL when no size is left, ignoring the error while it is loaded, then `apply()`). Nothing is downloaded at startup or while the engine is Windows; the frontend starts a download when the engine or size changes to a size that is not ready.
- `update.rs`: OTA updates over `tauri-plugin-updater` (endpoint `snapr-releases/releases/latest/download/latest.json`, minisign `pubkey` and passive NSIS per-user install in `tauri.conf.json`). `State.update` holds the status (`idle | checking | latest | available | blocked | downloading | installing | error`, plus version, progress and error), the found `Update`, the `announced` version (one notification per version per run, en/vi) and whether the tray item is listed. `update::start` runs a silent check 10 s after launch, then every 6 h while `update_check` (not in debug builds); a failed automatic check shows nothing. `settings::save` runs a check when `update_check` turns on. A found version inserts `State.upgrade` ("Update to x.y.z" / "Cập nhật lên x.y.z") into `State.menu` above Quit and removes it when no update is found; its menu event opens About and installs. `update_install` refuses (`blocked`) while `State.recording` is `Some` or `State.counting` (set while `Snap.countdown` is `Some`), checks again after the download, then `install` runs the installer and exits the process (`cleanup_before_exit` first). Commands `update_status`, `update_check` (manual, ignores the setting), `update_install`; every change emits `update-status` (progress throttled 100 ms). Nothing installs without the user's click.
- `settings.rs` holds the commands the settings window invokes, plus the HKCU `Run` registry autostart.
- `gallery.rs` lists the output folder (png/mp4 only, no subfolders, `date = min(created, modified)`, newest first) and holds the gallery commands. `guard(app, path)` requires the canonical parent to equal the canonical output folder and a png/mp4 extension; every command and scheme goes through it, so `..\` or outside paths fail. `gallery_delete` uses `SHFileOperationW` (Recycle Bin); `gallery_copy` refuses mp4; `gallery_pin` refuses non-photos and sends `Action::Pin` to the capture thread; `gallery_text` refuses non-photos and returns `Recognized { qr, text }` (an OCR failure is an error only when no QR code decoded). `gallery_delete_many` validates every path before deleting and reports per-file failures; `gallery_copy_files` puts photo files on the clipboard as `CF_HDROP`; `gallery_pin_many` sends `Action::PinMany`.
  - Two async URI schemes are registered in `run`: `thumb` returns Windows Shell thumbnails (`IShellItemImageFactory`) from an STA worker pool, as PNG with `Cache-Control: max-age=3600`; `media` serves the full file with `Range` (206 + `Content-Range`). Both return 404 on a guard or Shell failure.

Settings window ↔ backend:
- The JSON contract uses snake_case fields, while command argument names are camelCase on the JS side.
- Commands: `load`, `defaults`, `resolve_dir`, `check`, `save`, `open_folder`, `open_config_file`, `open_settings`, `open_language_settings` (spawns `explorer ms-settings:regionlanguage`). `check` takes `text` (text slot active); `load` returns `ocr_available` (Windows OCR or the selected Paddle model ready) and `windows_ocr`. PaddleOCR commands (`paddle_status`, `paddle_download`, `paddle_cancel`, `paddle_delete`) live in `paddle.rs`. Gallery commands (`gallery_list`, `gallery_open`, `gallery_reveal`, `gallery_copy`, `gallery_copy_files`, `gallery_pin`, `gallery_pin_many`, `gallery_text`, `gallery_delete`, `gallery_delete_many`) live in `gallery.rs`.
- `save` is called on every change from the settings view (autosave; no Save/Cancel). The setup view saves once on Start.
- `save` applies immediately by calling `apply()` in `lib.rs`, which unregisters all hotkeys, re-registers them and updates the tooltip. There is no restart and no file polling.
- `check` reports hotkey errors (`invalid` / `needs_modifier` / `duplicate`) and `in_use`.
  - `in_use` is probed by test-registering the combo.
  - A combo snapr itself has registered counts as free.
- One frameless (`decorations: false`), transparent, Mica, non-resizable `main` window is used for three views: splash (480x300, first run only, shown from `setup`), setup (first run) and settings (sidebar: Gallery / Settings; Settings is one scrollable page stacking General / Capture / Text / Recording / Hotkeys / About via `settings/preferences/preferences.tsx`, under a sticky jump bar; the preview toast row (Switch, off = `preview_seconds` 0, plus a seconds slider) lives in General; Capture shows only the padding switch until it is on, then size / radius sliders (`settings/slider-field.tsx`, saves on release) and a Transparent / Windows wallpaper / Image background ToggleGroup mapped onto `padding.image` + `padding.wallpaper`; Gallery is the only `wide` one).
  - `show_settings(app, section)` sizes it to `min(1366x768, monitor work area)`, centers, shows and emits `settings-open` with the section id. The tray menu is Gallery (`"gallery"`), Settings… (`"settings"`), Open folder, Stop recording, the update item (only while an update is available), Quit; the update item passes `"about"`, which `use-settings` maps to the Settings section plus `group`, and `Preferences` scrolls to that group; `open_settings` and the splash also pass `"settings"`.
  - `Saved` and `Recorded` emit `gallery-changed` to `main`.
  - Drag via `data-tauri-drag-region`. The X button and Escape hide the window.
  - Closing the window hides it instead of exiting.
  - The frontend hides itself via `getCurrentWindow().hide()`.
- `src/App.tsx` only picks the view (splash / setup / settings) from `useSettings`.
- `lib/api.ts`: types and typed wrappers for every Tauri command; `invoke` is called only here. `lib/i18n.ts`: the `{ en, vi }` table `T` (default `vi`). `lib/hotkeys.ts`: `MODS`, `SLOTS`, `normalize`. `lib/app-info.ts`: `APP_INFO` (name, author, links) used by the sidebar, splash, About and i18n.
- `hooks/use-update.ts` reads `update_status` on mount and `settings-open` and follows `update-status`; `use-settings` exposes it as `updater`. General shows `general/update-check-row.tsx` (the `update_check` Switch); About shows `about/update-row.tsx` (Check now / spinner / up to date / version + Update / Progress / installing / error + Retry, which installs when a version is known and checks otherwise).
- `hooks/use-paddle.ts` holds `paddle_status`, the `paddle-progress` / `paddle-done` listeners (a successful done reloads `ocr_available`) and download / cancel / delete; `use-settings` exposes it as `paddle` and starts a download after a save that switches the engine or size to a size that is not ready. The Text group (`settings/text/`) shows `text-capture-row.tsx`, `ocr-engine-row.tsx` and, only for the paddle engine, `paddle-model-row.tsx` (size ToggleGroup, description, Vietnamese note, Progress + Cancel / inline error + Retry / Download) and `paddle-models-row.tsx` (per-size Badge, disk size, Delete with an AlertDialog). `hooks/use-settings.ts` owns state, load, autosave (`persist`) and the `settings-open` listener (`load(true, section)` selects the section); `hooks/use-hotkey-recorder.ts` owns key recording and skips `defaultPrevented` events (the gallery viewer handles its own Escape).
- `lib/gallery.ts` (`groupBy(items, period)` driven by the `PERIODS` mapping for day / month / year, `matches`, `isViewable`) and `hooks/use-gallery.ts` (items, filter, period, collapsed group keys (a `Set`, in memory only, kept across reloads), viewer index over photos and videos only (`kind: "other"` files are skipped by navigation, strip and delete-in-viewer), copy/pin/delete; reloads on mount, `settings-open` and `gallery-changed`; delete moves the viewer to next, else previous, else closes; `pin` hides the settings window after the command succeeds. Selection state (`selected`, `selectMode`, `anchor`), long-press/Ctrl/Shift/Ctrl+A/Esc, the flat filtered `visible` list and the bulk copy/pin/delete actions live here; a reload prunes missing selected paths and filter/grouping changes clear the selection).
- `components/settings-provider.tsx` exposes it through `useSettingsContext()` (no prop drilling); `components/title-bar.tsx` is the drag strip + X.
- Screens live in `components/splash/`, `components/setup/`, `components/settings/` (groups in `gallery/`, `general/`, `capture/`, `text/`, `recording/`, `hotkeys/`, `about/`, one file per row). A new sidebar page = a folder + an entry in `settings/sections.ts`; a new group on the Settings page = a folder + an entry in `GROUPS` in `preferences.tsx`.

## Conventions

- No code comments.
- Always build UI from the existing shadcn components in `src/components/ui/`. Don't hand-roll native `<input>`/`<button>` or custom equivalents.
- Keep it minimal: reuse v1 code over rewriting, no speculative abstractions.
- Add new Tauri plugin permissions to `src-tauri/capabilities/default.json`.
- Barrels: only screen roots (`components/splash|setup|settings/index.ts`) have an `index.ts`. Import a screen from outside via `@/components/<screen>`; inside a screen use relative paths, never its own barrel. `components/ui/` and `title-bar.tsx` never import screens.
