# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Snapr: a Windows-only tray screenshot app (fullscreen, window, area capture with global hotkeys and a preview toast).
Tauri 2 backend in `src-tauri/`, React 19 + TypeScript + Tailwind v4 + shadcn (base-ui, "base-vega") settings UI in `src/`.
It is a port of the v1 winit app at `V:\source\repos\snapr` (commit `8ac4086`).

## Commands

Use **bun**, never npm/pnpm.

- `bun run tauri dev`: run the app (starts Vite on port 1420, strict)
- `bun run tauri build`: release bundle (NSIS only, plus the bare `target/release/snapr-v2.exe` that releases also publish; `createUpdaterArtifacts` needs `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` set, or the build fails at signing)
- Release: bump the version in `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` and `package.json`, commit and push, then run the Release workflow by hand (Actions tab or `gh workflow run release.yml [-f notes=...]`; `workflow_dispatch` only, no tag trigger). `.github/workflows/release.yml` checks the three versions match and that `v<version>` is not already on `snapr-releases`, builds and signs on `windows-latest` and publishes the installer, `.sig` and `latest.json` to the public `quanvudev/snapr-releases`, then copies `snapr-v2.exe` to `Snapr_<version>_x64.exe`, signs it with `tauri signer sign`, uploads it and its `.sig` and runs `scripts/scoop.ts` (secrets `RELEASES_TOKEN`, `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`). The source repo stays private.
- `bun run release`: local alternative to the workflow. Requires the three versions to match and a clean tree, refuses a version already on `snapr-releases`, signs with `~/.tauri/snapr.key` + `snapr.key.password` (or the env vars), builds, signs the bare exe the same way, writes `latest.json`, creates the release with `gh` targeting `main` (installer, exe, both `.sig`, `latest.json`) and runs `scripts/scoop.ts`. It does not tag the source repo; do not also run the workflow for the same version (it refuses an existing release anyway).
- `scripts/scoop.ts <version> <exe> [gh]`: renders the Scoop manifest (bare exe URL `#/snapr.exe`, SHA-256, `bin`, Start menu shortcut, `checkver` / `autoupdate` on `snapr-releases` tags, an uninstaller script that removes the HKCU `Run` `snapr` value when it points into the Scoop app folder) and PUTs it to `bucket/snapr.json` on `snapr-releases` through `gh api`, which makes that repo the Scoop bucket (`scoop bucket add snapr https://github.com/quanvudev/snapr-releases`); `SCOOP_DRY_RUN=1` only prints it.
- `/release [major|minor|patch|x.y.z] [--yes]` (`.claude/skills/release/`): reads the commits and the diff (openspec deltas first, then config, tray, commands, i18n and settings UI) since the last `snapr-releases` release, decides the semver bump from user-visible impact, prepends a `CHANGELOG.md` entry and uses it as the release notes, asks to confirm unless `--yes`, bumps the three versions and `Cargo.lock`, commits `chore: release v<version>` with `CHANGELOG.md`, pushes master (no tag) and runs `bun run release <notes>`.
- `$env:SNAPR_RECORD_SECS=10; bun run tauri dev`: debug builds only, every recording stops itself after that many seconds (wall clock, pauses included), for repeatable frame-rate tests
- `bunx tsc --noEmit`: type-check the frontend
- `cargo clippy` (in `src-tauri/`): lint the backend
- `bunx --bun shadcn@latest add <component>`: add a shadcn component to `src/components/ui/`

There are no tests.

## Architecture

The app runs **two event loops in one process**:

- **Tauri (tao) on the main thread** owns the tray, global hotkeys (`tauri-plugin-global-shortcut`), the settings webview window (label `main`) and config state.
- **A winit event loop on a dedicated thread** (`spawn_capture` in `src-tauri/src/snap.rs`, built `with_any_thread(true)`) owns the native capture overlay, the preview toast and screen pins.
  - The capture overlay (window/area/text/record pickers) covers all monitors (`overlay::desktop()` stitches every monitor into one frame over the union rect), while fullscreen capture, the toast and the record-picker desktop fallback stay on the cursor's monitor.
  - This split exists because Tauri window events carry no mouse or keyboard input, which the overlay needs.
  - Hotkey handlers send `Action` (Fullscreen / Pick(Window) / Pick(Area) / Text / Record / Draw / Ring) through an `EventLoopProxy` that is stored in managed `State`. There are seven hotkey slots (`Hotkeys::combos()` is `[String; SLOTS]` with `SLOTS = 7`, order fullscreen, window, area, text, record, draw, ring). `Hotkeys.mode` is `fixed` (default, the original model: the shared `modifiers` prefix plus a bare key per slot, `combos()` prefixes unless the key has a `+`, is a mouse binding or is empty) or `manual` (`Hotkeys.manual`, one full combo per slot, no prefix; stored separately so switching modes never overwrites either set, and the first switch to manual seeds it from the resolved fixed combos in `ModeRow`). A config without `mode` loads as fixed unchanged. While a row records a combo the frontend calls `set_listening(true)`, which unregisters every global shortcut and the mouse hook so an already-mapped combo is recorded instead of firing; `set_listening(false)` (and `api.hide`, and a window `CloseRequested`) calls `apply()` to restore them. `text`, `draw` and `ring` have field-level `#[serde(default)]` so an older config without them stays unbound (empty) instead of colliding with an existing binding. `config::skipped(i, combos, text_active)` is the one place that skips an inactive or empty text slot and an empty draw or ring slot; `apply()` and `settings::rows` both use it.
  - Recording: the record hotkey / ring Record wedge (`trigger`) stops a running recording, else (not counting down) calls `panel::toggle` on the main thread, which opens or closes the setup panel (below). The setup bar's mode ToggleGroup (`PanelState.mode`, `config.record_mode`: `fullscreen` default / `window` / `area`, saved by `record_start`) picks how Start (`record_start`) continues: it sends `Action::RecordPick(mode)` and `Snap::record_pick` records the monitor under the cursor at once for `fullscreen` (`cursor_monitor`, straight into `begin`), opens the click-only window picker for `window`, or the area picker for `area`, both with `Snap.mode = Mode::Record`; cancelling the picker (or a pick that opens no overlay) calls `panel::cancelled` (back to Setup), a pick calls `panel::picked(bounds)` (compact panel; the camera window is created where the setup preview was, its centre saved as `Panel.anchor` by `record_start`, unless the mode is `area` or that spot is outside the bounds, then at the bottom-left inside them). A picked hwnd goes to `Recorder::start` (`recorder.rs`, `windows-capture`: WGC + H.264 MP4) as `Target::Window` instead of the save worker (a desktop `Progman`/`WorkerW` pick records the monitor under the cursor instead); with a camera selected (`panel::choices`) a window pick instead goes through `region_target(window_rect)` and records as `Target::Area` (the window is not followed). `Overlay::open` takes a `record` flag (true only for the area picker in `Mode::Record`): its release returns `Shot::Region { rect, start, hwnd }` (screen coordinates, `hwnd` = window under the start) instead of cropping. `region_target` clips the region to the monitor under the drag start (`frame::monitor_at`), rounds the size down to even and builds `Target::Area { monitor, rect }` (rect relative to the monitor, physical px); under 16x16 it falls back to a click at the start (window, or the monitor on the desktop). `Target::Area` runs a monitor WGC session, builds the encoder at the area size and sends each frame with `send_frame_region(frame, x, y, timestamp)`, a GPU `CopySubresourceRegion` with an explicit timestamp into the next of 8 rotating encoder surfaces (every target uses it, window and monitor with `(0, 0)`: the encoder reads surfaces asynchronously, so a single reused surface or the recycled WGC frame-pool surface gets overwritten before it is encoded and the video repeats frames); `keep()` crops on the CPU with `buffer_crop` every 2.5 s for the toast thumbnail. `send_frame_region` is not in upstream `windows-capture`: the crate is vendored at `src-tauri/vendor/windows-capture` (2.0.1, examples and dev-dependencies stripped) through `[patch.crates-io]`, with `build_padded_surface` generalised to `build_region_surface(frame, left, top)` and the single cached surface turned into a ring of `CACHED_SURFACES` (8). While an area recording runs, `Snap.frame` holds a `frame::Frame`: a click-through (`WS_EX_TRANSPARENT`), topmost, non-activating, `WDA_EXCLUDEFROMCAPTURE` layered window drawing a 2 px accent border just outside the area, dropped on `Recorded` / `RecordFailed`. Countdown: every record pick goes through `Snap::begin(target, bounds, area)`; with `record_countdown` on it hides pins (recording reason), opens a `frame::Digit` (layered, click-through, non-activating, excluded from capture, 160 logical px, centered on the target and clamped to its monitor), enables Stop and stores `Snap.countdown`; `tick_countdown` (from `about_to_wait`, deadline in the `WaitUntil` min) steps 3, 2, 1 once a second, then drops the digit and starts `record` 50 ms later, so the file name is the real start time. Cancel paths: `Action::Record` while `Snap.countdown` is `Some` cancels (`trigger` sends it only when `State.counting` is set; otherwise it toggles the panel), and the tray Stop item sends `Action::CancelCountdown` when `stop_recording` found no recorder; cancel and a failed start show pins again, disable Stop and restore the tooltip. Esc does not cancel (the digit window never takes focus). The recorder lives in `State.recording` (`Mutex<Option<Recorder>>`) so the main thread can stop it: the record hotkey (while recording), the tray "Stop recording" item (`State.stop`) and Quit take it out of the mutex, then call `stop()`, which finalizes synchronously. On stop or window close the handler finishes the file and sends `Action::Recorded`, which clears `State.recording`, restores the tooltip and opens the toast. Never hold `State.recording` while calling `stop()`. Audio and pause: `recording::record()` calls `panel::audio` (`audio::Capture::start(mic, speaker, record = true, ..)` from the panel choices), keeps the capture in `State.capture` and passes its `chunks()` receiver (only when `has_audio()`) to `Recorder::start`; with no receiver the encoder audio track is disabled. `ended()` (stop, `Recorded`, `RecordFailed`) drops the recorder and the capture, disables Stop and Pause, resets the Pause text and calls `close_panel` (`panel::close` on the main thread). `pause_recording(app, bool)` (the `record_pause` / `record_resume` commands and the tray Pause item) flips `Recorder::pause` / `resume`, calls `panel::paused`, toggles the tray text (Pause recording / Resume recording) and `refresh`es the tooltip (`Snapr: paused` / `Snapr: recording…`); `update_install` still refuses while paused.
  - The loop never encodes: it hands each capture to a background save worker thread as a `Job` (`Save(Shot)` / `Text(Shot)`) (`std::sync::mpsc`, started in `spawn_capture`). When `padding.enabled`, the worker first pads the image with `capture::pad` (transparent, or the `padding.image` background scaled to cover; with no image and `padding.wallpaper` on, the current desktop wallpaper from `capture::wallpaper()` (`SPI_GETDESKWALLPAPER`, empty for a solid colour, which pads transparently) is used instead; backgrounds decode with a content-guessed format, since the wallpaper is often the extensionless `TranscodedWallpaper`), so the file, clipboard and toast all get the padded image; a background load error pads transparently and is shown in the tooltip after `refresh`. The worker saves the PNG, reports back with `Action::Saved` (which opens the toast), then copies to the clipboard. It caches the decoded `padding.image` in a `BackgroundCache` keyed by path + modified time.
  - Text capture: `Action::Text` opens the area picker in `Mode::Text`; the worker (WinRT initialized MTA once) runs `read_text`: `ocr::qr` (`rqrr`, luma downscaled to 2000 px on the longer side, codes sorted top to bottom) first, and when any QR code decodes it copies them one per line and notifies "QR code copied" (or a count), otherwise `ocr::extract` with the selected engine; it copies with `arboard` regardless of `copy_to_clipboard`, and reports via `tauri-plugin-notification` from Rust (en/vi strings in `jobs.rs`), never the toast. The text hotkey is registered only when `text_capture && State.ocr`; `State.ocr` caches `ocr::available()`, re-probed in `apply()` and in `show_settings()` (which re-applies when it changed). `settings::rows` skips an inactive or empty text slot (no error, no in_use, no duplicate). The pin Copy text button (`pin::Outcome::Text`, the pin's full-resolution image) sends the same `Job::Text`. The gallery does not touch the clipboard: the async `gallery_text` command decodes the photo on a `spawn_blocking` thread (WinRT MTA), runs `ocr::qr` and `ocr::extract` and returns `{ qr, text }` to the viewer's text pane; both are offered only while `State.ocr`, regardless of `text_capture`.
  - Draw capture: `Action::Draw` opens the area picker with `Overlay::open(.., draw = Some(Snap.style))` in `Mode::Shot` (`None` for every other picker). An area release enters an annotating phase (`Annotation { sketch, toolbar, hover, palette }`) instead of saving. The selection stays editable: eight handles (corners and edge midpoints; `HANDLE_HIT` 14 logical px hit zone, `HANDLE_SIZE` 8 drawn squares, hit before the toolbar and before drawing, matching resize cursors; state in `Annotation.adjust` / `space` / `label`) resize it live, and holding Space (not while a text box is open) and dragging inside it moves it; the rect is normalised (min 3x3, clamped to the frame) and `Sketch::reselect` re-crops the background from the frozen frame and translates shapes, undo / redo snapshots, the open text box and the drag so shapes keep their screen position (parts outside the final selection are clipped). Selection changes are not undoable. A `W × H` physical-px size label sits at the selection's top-left (above it, else inside), a `toolbar::tag` pill (shared with the tooltip), drawn in `overlay::draw` only, never in `finish()`. The toolbar is two rows: a fixed main row (the constant `MAIN_ROW`: rectangle, ellipse, arrow and text tools, Undo / Redo, Pin / Copy, Done / Cancel, same positions for every tool) and an options row for the active tool or selected shape, on the side of the main row away from the selection and hidden when empty. The toolbar is centred on the selection and re-placed after a resize or move ends. Rectangle and ellipse (drawn or selected) show an Outline only | Outline and fill icon pair (hollow square / filled tinted square, current one marked; `StrokeStyle.fill`, key F toggles; tooltips vi Chỉ viền / Viền và tô), an outline colour button (hollow ring in the colour), a fill colour button (filled square, `StrokeStyle.fill_colour`, default same as outline, picking one turns fill on) only in fill mode and thin / medium / thick widths (each button draws a bar of the real thickness); arrow shows the outline colour button and widths; text shows the text colour button (filled circle), size down / current size / size up, bold and italic. The toolbar has no text. There is no popup: a colour button click sets `Annotation.palette` and the options row is replaced by a palette row (that colour button marked current, a divider, 8 swatches; no Back or caption); clicking that button again, a swatch (applied first), Esc, a tool switch or any click elsewhere closes it. A filled shape is also hit and moved from its inside. Placement tries below the selection, then above it, then inside its top edge (by the combined height of both rows, so the options row appearing never flips the side), clamped to the selection's monitor rect (`desktop()` returns the monitor rects, relative to the overlay origin). Keys: R/C/A/T switch tools (not while a text box is open), `[` / `]` step the width (shape tools) or the text size, Ctrl+B / Ctrl+I toggle bold / italic with the text tool (also while typing), Ctrl+Z undoes, Ctrl+Y / Ctrl+Shift+Z redoes, Ctrl+C copies (not while a text box is open), Ctrl+P pins, Ctrl+S / Enter / ✓ Done saves, Esc / ✗ cancels. Undo and Redo are dimmed and ignored when unavailable: `overlay::enabled(sketch, button)` filters `hit` results. Holding Shift while dragging makes a square or circle (sized by the larger side) or snaps the arrow to 45°, live and on release. While a text box is open, typed text goes into it (Enter adds a newline, Backspace deletes, Esc commits it). With any tool, hovering a shape's outline (or a text shape's box) shows the Move cursor; a press there moves the topmost hit shape (live) and selects it, any other press draws and clears the selection. The selected shape gets a dashed accent box in `view()` only (never in `finish()`); Delete removes it; the toolbar then shows that shape's kind and style, and an option click or `[` `]` Ctrl+B Ctrl+I restyles it and becomes the current style. Escape closes an open palette first, then clears the selection, then commits an open text box, then cancels. Undo is a snapshot stack of `Vec<Shape>` pushed before every add, move (once per drag), delete and restyle; `Sketch.redo` holds the undone snapshots: `snapshot()` clears it, so a move snapshots lazily on its first real delta; Ctrl+Z discards an open text box first (leaving `redo` alone). Right-click is ignored while annotating. Done returns `Outcome::Save(Shot::Ready(..))` through the normal save worker. Copy returns `Outcome::Copy(RgbaImage)` handled in `snap.rs`: `capture::copy` on the capture thread, clipboard only (no file, padding or toast; errors in the tooltip). Pin returns `Outcome::Pin(RgbaImage)`: `Pins::add` after `show_capture`, no file or padding. Neither uses the save worker. `Snap.style` (`draw::Style`) keeps the chosen colours, width, size, bold and italic until snapr quits: `window_event` takes `Overlay::style()` back on save, copy, pin or cancel. It is never written to the config.
  - Action ring: `Action::Ring` opens `Ring` (`ring.rs`), a transparent per-pixel-alpha (`UpdateLayeredWindow`) native winit window centred on the cursor and clamped to its monitor, drawn with tiny-skia in the Logitech Actions Ring style: eight floating black round icon buttons (Segoe Fluent Icons) on a circle, a white label card beside each and a small centre x that cancels. One `WEDGES` table (label, vi label, glyph) drives layout and hit-testing; buttons and cards both pick. The settings ring page draws the same glyphs: `BUILTINS[id].glyph` and `GENERIC_APP_GLYPH` in `lib/ring.ts` mirror `WEDGES` and `APP_GLYPH` and render through `Glyph` (`ring-icon.tsx`, Segoe Fluent Icons with the MDL2 fallback); change both sides together. `Snap::open_ring` passes the wedges in display order (Fullscreen, Window, Area, Text, Record, Draw, Gallery, Settings), with Text only when `text_capture && State.ocr`, and the Record wedge reads Stop recording while `State.recording` is `Some`. The hotkey toggles it closed and is ignored while an overlay is open. Esc, a centre or outside click, losing focus (`Ring::open` activates it through `AttachThreadInput` to the foreground thread, since a hook-swallowed mouse trigger leaves `SetForegroundWindow` blocked; `tick` also closes it after `FOCUS_GRACE` once it lost the foreground it had, or on a left / right press off the buttons, so a ring that never got focus still closes) and `ring.idle_close` seconds without input (default 5, 0 = never; no cursor move, key or click on the ring and no button hovered; read at open, picked from a Select on the ring page) cancel it. A pick drops the ring first, then `wedge_action` maps it after `RING_HIDE_DELAY` so the picker's frozen frame never contains the ring: capture wedges go through `trigger` (Record stops a running recording), Gallery and Settings call `show_settings`. The ring hotkey may also be a mouse button (`Mouse3` middle, `Mouse4` back, `Mouse5` forward, optional `Ctrl+`/`Alt+`/`Shift+`; never prefixed with the shared modifiers): `mouse.rs` runs a `WH_MOUSE_LL` hook thread that swallows the exactly-matching press and its release and sends `Action::Ring`; `apply()` binds the hook for a mouse ring combo (`config::is_mouse`) and the shortcut plugin otherwise, `settings::rows` skips needs-modifier and in-use for it, and only the ring row of the hotkey recorder accepts the mouse.
  - Screen pins: `Action::Pin(PathBuf)` (the toast Pin action or the `gallery_pin` command) decodes the file and `pin.rs` creates a frameless, always-on-top, non-activating layered window (`UpdateLayeredWindow`, per-pixel alpha; reuses `ring::bitmap` / `ring::present`) centred on the cursor and clamped to the work area, capped at about 250 logical px on the larger side (DPI-scaled) with smaller images at 1:1. A pin draws the image 1:1, drags with `SetCapture` / `GetCursorPos`, and shows a hover toolbar (Copy `E8C8`, Copy text `E8D2` only when `State.ocr` was true at `Pin::open`, Close `E711`, check flash `E73E` on Copy only); Copy and Copy text use the original full-resolution image, and the window's minimum size grows with the button count. `Pins` keeps independent `capture` and `recording` hide reasons: pins hide before `Overlay::open`, before `capture::fullscreen` and before `record(...)`, and reappear when the last reason clears, so a screenshot during a recording keeps them hidden; they are not `WDA_EXCLUDEFROMCAPTURE`, so other apps' screen shares see them. `Action::PinMany(Vec<PathBuf>)` creates one pin per path with a 24px cascade for the gallery's bulk Pin; `Pin::open` takes the placement offset. Pins are in-memory only and disappear on quit. The toast shows its Pin action only while hovered and only on screenshot toasts (`Toast::open` takes `pinnable`; `Action::Recorded` passes false).
  - The capture thread reads config from `State.cfg` (`RwLock`) and reports status and errors through the tray tooltip.

Backend modules:
- `lib.rs` is wiring only: the `mod` list, `Action` (the capture-thread message enum), `State` (managed state) and `run` (plugins, URI schemes, `setup`, the window close handler, `invoke_handler`). Behaviour lives in the modules below; there are no `pub use` re-exports.
- `snap.rs`: the winit capture thread. `spawn_capture` (starts the loop and the `jobs` worker, returns the proxy), `Snap` and its `ApplicationHandler<Action>` impl (overlay, ring, toast, pins, countdown and record-target routing), `Mode`, `Countdown` and the record target helpers `is_desktop`, `cursor_monitor`, `window_rect`, `region_target`.
- `capture.rs`, `overlay.rs` and `toast.rs` come from v1. `overlay.rs` and `toast.rs` re-apply their physical size and position after `create_window` (mixed-DPI fix), and the overlay spans all monitors.
  - Win32 capture uses `PrintWindow` + DWM bounds, with rounded corners added.
  - Saves a timestamped PNG and can also copy the image to the clipboard. `capture::unique_path(dir, ext)` gives the timestamp + `_N` name for both PNGs and recordings; it calls `capture::stem_path(dir, stem, ext)` (`<stem>.<ext>`, else `_1`, `_2`…), which the GIF export uses with the video stem.
- `config.rs` holds the TOML config at `app_config_dir()/config.toml` (`%APPDATA%\com.quanvudev.snapr`).
  - The path is resolved in `setup` and stored in `State`.
  - `load` returns defaults without writing when the file is missing; only `save` creates it. A missing file means first run.
  - `parse_hotkey` maps `Win` → `Super`.
  - `record_countdown` (`#[serde(default)]`, off) turns the 3-second countdown on; it is read at pick time.
  - `update_check` (default true, so an older config loads with it on) turns the automatic update check on.
  - `record_mic` (`"default"` default, `""` none, else a device id), `record_camera` (`""` off, else a WebView2 `deviceId`) and `record_speaker` (`""` no system audio, `"default"` the Windows default output, else an output device name) are written by `record_start` (the panel is their only UI) and read by `panel::open`.
  - `record_fps` is read only through `Config::fps()`, which returns 60 for 60 and 30 for anything else; `recorder.rs` derives both the frame throttle and the encoder rate from it.
  - `record_quality` (`"low"` / `"medium"` default / `"high"`, field-level `default_quality` so an older config loads as Medium) is read only through `Config::quality()` (`video::Quality`, unknown values map to Medium); `record()` reads it with the fps and `Recorder::start` passes `.bitrate(video::bitrate(w, h, fps, quality))` to `VideoSettingsBuilder`, replacing the vendored encoder's fixed 15 Mbps default. A recording keeps the quality it started with.
  - `record_compress` (`#[serde(default)]`, off) and `record_compress_height` (default 1080, read through `Config::compress_height()`, which returns 720 for 720 and 1080 for anything else) turn on automatic compression: `Action::Recorded` (after the discard check, before the preview) calls `video::compress_recording(app, path, height, cfg.quality())`, which probes the height with `gif::probe` on its own thread (the event loop never blocks) and, only when the recording is taller than the target, adds a replace-mode `CompressTask` through `State.queue.add` (the first queue producer outside a command). The preview opens at once as before; a smaller recording queues nothing.
  - `record_transcribe` (`#[serde(default)]`, off), `whisper_model` (`WhisperModel` `base` / `small` default / `turbo`, `#[serde(default)]`) and `transcript_language` (`auto` default / `vi` / `en`, field-level default, read through `Config::transcript_language()`, which maps an unknown value to `auto`) configure transcription; an older config loads with it off, Small and Auto-detect. `Action::Recorded(img, path, has_audio)` carries `has_audio` (the recorder had an audio receiver at start, `audio.is_some()`); after the discard check and before `compress_recording`, when `record_transcribe && has_audio`, `Snap::queue_transcript` builds `TranscribeTask::validated` and adds it to `State.queue` synchronously (a missing model or any refusal queues nothing and shows no error), so the transcribe item is always ahead of the compress item, which is queued later from its probe thread. A replace-mode compression keeps the original path, so the `.srt` name still matches; if the recycle fails and the result is `_compressed.mp4`, the transcript stays with the kept original.
- `draw.rs`: `Tool` and the closed `Shape` enum with `render`, drawn by tiny-skia. Each shape keeps the `StrokeStyle { colour, width }` or `TextStyle { colour, size, bold, italic }` it was drawn with (`PALETTE`, `WIDTHS`, `SIZES`; defaults red, 4, 20 regular); an open text box uses the current `TextStyle`. Text goes through `ab_glyph` with `%WINDIR%\Fonts\segoeui.ttf` loaded lazily (the text tool is disabled if it fails); bold / italic / bold-italic (`segoeuib`, `segoeuii`, `segoeuiz`) are looked up by `(bold, italic)` and fall back to regular. `system_font(files)` is the shared loader, also used for the toolbar icon font. `Sketch` holds the editing state, a cached layer of committed shapes, `view()` for the live preview and `finish()` for the saved image, plus `reselect(frame, rect)` (re-crop and translate, see Draw capture) and the `history` / `redo` stacks with `can_undo()` / `can_redo()`.
- `toolbar.rs`: `Button` (tools, `Undo`, `Redo`, `Pin`, `Copy`, save (the Done ✓) and cancel, and the options: `Colour` and `FillColour` (the icon-only colour buttons), `Outline`, `Fill`, `Width(i)`, `Smaller`, `Larger`, `Bold`, `Italic`; `Swatch(i)` only in the palette row), `Palette` (`Stroke` / `Fill`, which colour the open palette row picks), `Toolbar::place(selection, monitor, scale, vi)` (centred, `main` and `options` rects), `hit(at, kind, fill, palette)` (does not know about disabled buttons; `tooltip` takes the palette too), `render(tool, kind, style, hover, palette, &dyn Fn(Button) -> bool)` returning `Vec<(&Pixmap, (i32, i32))>` (main row, then the options or palette row when non-empty; the active tool and current options marked; the closure dims disabled buttons), `tag(text, scale)` (the pill shared by tooltips and the size label), `tooltip` and `shortcut`. - `onnx.rs`: the one ONNX Runtime shared by PaddleOCR and Whisper. It owns the `onnxruntime` cp313 win_amd64 wheel on PyPI (`RUNTIME` remote with SHA-256 and size; only `onnxruntime/capi/onnxruntime.dll` is extracted, through `.part` and rename) and `runtime_path(app)`, still `paddle/onnxruntime.dll` so existing installs keep their DLL. `missing_bytes(app)` is the wheel size while the DLL is absent (added to both stores' download totals); `ensure(app, fetch)` downloads and extracts it when absent (used by `paddle.rs` and `whisper.rs`; a race between the two only downloads it twice). `init(path)` runs `ort::init_from` once per process in a `OnceLock` (an absolute path, because Windows 11 ships its own `System32\onnxruntime.dll`; an error is cached too) and `environment()` returns the initialised one (or an error when `init` has not run), which the Whisper engine uses. `release(app, busy)` deletes the DLL only when `busy` is false and neither `paddle::installed` nor `whisper::installed`; the error is ignored while the DLL is loaded, since it cannot be deleted while the process runs. `busy` is the other store's download slot, read before the caller takes its own lock, so the two delete commands never nest the locks.

Files live in `app_local_data_dir()/whisper/<model>/`; `ready(app, model)` is all six files plus the runtime DLL, `installed(app)` is any model folder existing, `model_dir(app, model)` is the folder. One download at a time in `State.whisper_download` (`Download { model, cancel, done, total }`, independent of Paddle's slot) on its own thread: it cleans `.part` files, `onnx::ensure`s the runtime, fetches the six files and removes the whole model folder on failure or cancel; it emits `whisper-progress { model, done, total }` (throttled 100 ms) and `whisper-done { model, error }` (`error: null` on success and on cancel; no `apply()`, hotkeys are unaffected). Commands: `whisper_status` (`{ ready, bytes, downloading }`, `bytes` = the pinned size of each model for display), `whisper_download(model)`, `whisper_cancel`, `whisper_delete(model)` (refuses the downloading model and the one in `IN_USE`, removes the folder, then `onnx::release`). `IN_USE` is a static `Mutex<Option<WhisperModel>>` set by `acquire(model)`, whose `UseGuard` clears it on drop; `TranscribeTask::run` holds it. Nothing is downloaded at startup; the frontend starts a download when automatic transcription turns on or the model changes to one that is not ready.
- `transcript.rs` + `transcript/`: transcription of an MP4's speech into a sidecar SRT, entirely local. `pcm(path, cancel, progress)` reuses `gif::Media` and an `IMFSourceReader` with only `MF_SOURCE_READER_FIRST_AUDIO_STREAM` selected and the output typed as float mono 16 kHz (`open_audio(path, &AudioFormat { subtype, rate, channels, bits })`, `WHISPER_AUDIO` here, the PCM i16 48 kHz stereo of `subtitle.rs` there; the reader inserts the decoder and resampler), reading every sample into one `Vec<f32>` through the shared `read_audio(reader) -> Option<(bytes, timestamp_hns)>`; a failure selecting the audio stream is `NO_AUDIO` (the exact string the frontend maps to i18n), a failure typing it is the raw error; cancel is checked between samples. `MODEL_MISSING` is the other exact error string. `TaskSpec::Transcribe { path }` is the third queue kind (`"transcribe"`, `name` = the video file name, `source` = the video): `TranscribeTask::validated` (`video::guarded_mp4`, then `whisper_model` and `transcript_language` read from `State.cfg` through `Config::transcript_language()`, which maps an unknown value to `auto`, `MODEL_MISSING` when `whisper::ready` is false) fixes model and language at queue time. `run` holds `whisper::acquire`, runs `pcm` as the first 10 % of the 0-100 progress, `onnx::init`, then `decode::transcribe(model_dir, language, pcm, progress, cancel)` over the remaining 90 %, and writes `<stem>.srt` through `queue::write_part_to` with the final path fixed to `<stem>.srt` (`std::fs::rename` replaces on Windows, so a re-run overwrites and a cancel or error keeps the old file, with no `.srt.part` left). The SRT is written (`render_srt`, `HH:MM:SS,mmm --> HH:MM:SS,mmm`, numbered cues) and read (`parse_srt`, hand-written, BOM and CRLF tolerant, multi-line text joined with a space) in the same module; `Segment { start_ms, end_ms, text }` lives here. The `transcript_read(path)` command (`guarded_mp4`, `<stem>.srt`) returns the segments, `null` when the file does not exist and an error for a path outside the output folder; `transcript_save(path, segments)` (`guarded_mp4`, refuses `TRANSCRIBING` while `Queue::has("transcribe", path)`, then `write_part_to` to `<stem>.srt`) overwrites the SRT atomically with the full segment list (`Segment` is `Deserialize`); `parse_srt` and `SRT_EXT` are `pub(crate)`. The engine is Whisper ONNX through `ort` (no native build step; `whisper-rs` was tried and cannot build with MSVC without libclang): `mel.rs` is the log-mel front end (400-sample FFT, hop 160, 30 s window of 3000 frames, Slaney filters with the model's `feature_size` of 80 or 128 bins), `tokens.rs` loads `vocab.json` and decodes byte-level BPE ids to text, and `decode.rs` runs `decode::transcribe` over 30 s windows: the encoder session, language detection from one decoder step over the language tokens (only for `auto`, kept for later windows), then greedy decoding with the merged decoder and its KV cache (`past_key_values.*` fed from the previous `present.*`, the encoder cache kept, `use_cache_branch`, at most 224 tokens per window), Whisper's timestamp rules (no consecutive timestamps without text, monotonic timestamps, timestamp versus text probability comparison, `suppress_tokens` / `begin_suppress_tokens` from `generation_config.json`) without the initial-timestamp cap, then segments cut at timestamp pairs and a seek to the last timestamp (or the full window) for the next window. Cancel is checked between decoder steps and windows (`Err(queue::CANCELLED)`); the sessions are dropped after each task.
- `update.rs`: OTA updates without an updater plugin, the same for an installer copy and a Scoop copy. `check` reads only `version` from `snapr-releases/releases/latest/download/latest.json` (`ureq` through `fetch::agent()`, on `spawn_blocking`) and compares it with `semver`; `latest.json` and the installer `.sig` are still what `tauri-action` / `createUpdaterArtifacts` produce, so copies at 1.8.0 or earlier (on the old updater plugin) update through the installer once. `State.update` holds the status (`idle | checking | latest | available | blocked | downloading | installing | error`, plus version, progress and error), the found version, the `announced` version (one notification per version per run, en/vi) and whether the tray item is listed. `update::start` runs a silent check 10 s after launch, then every 6 h while `update_check` (not in debug builds); a failed automatic check shows nothing. `settings::save` runs a check when `update_check` turns on. A found version inserts `State.upgrade` ("Update to x.y.z" / "Cập nhật lên x.y.z") into `State.menu` above Quit and removes it when no update is found; its menu event opens About and installs. `update_install` refuses (`blocked`) while `State.recording` is `Some` or `State.counting` (set while `Snap.countdown` is `Some`), then downloads `v<v>/Snapr_<v>_x64.exe.sig` and the exe (by naming convention), verifies the minisign signature against `plugins.updater.pubkey` read from `app.config()` (`minisign-verify`, both base64; the block holds only `pubkey` and stays because `createUpdaterArtifacts` refuses to sign the installer without it), checks the recording block again, writes `<exe>.new`, renames the running exe to `<exe>.old` and `.new` into its place, spawns it with `--after <pid>` (each step rolls back on failure), sets `DisplayVersion` under `HKCU\...\Uninstall\Snapr` only when its `InstallLocation` is the exe's folder, then `cleanup_before_exit` and exits. `update::handoff()` at the top of `run()` waits (10 s cap) for the `--after` process so hotkeys are free and deletes `<exe>.old`. Commands `update_status`, `update_check` (manual, ignores the setting), `update_install`; every change emits `update-status` (progress throttled 100 ms). Nothing installs without the user's click.
- `subtitle.rs`: `SubtitleTask` (kind `subtitle`, `source` = the video) burns the transcript into a copy of an MP4. `SubtitleTask::validated` (from `into_task`) runs `video::guarded_mp4`, reads and parses `<stem>.srt` (`transcript::parse_srt`), drops segments whose trimmed text is empty, refuses `NO_TRANSCRIPT` when the file is missing or none are left and `NO_FONT` when `draw::system_font` finds neither Segoe UI Bold nor Regular (`segoeuib.ttf`, then `segoeui.ttf`); the segments are stored in the task, so later edits never reach a queued export. Frames come from `gif::open` / `Video::read` / `Video::image` and the audio from `transcript::open_audio` typed as PCM i16 48 kHz stereo (`AudioFormat`); a source with no audio track (`NO_AUDIO`) gives an output with the encoder audio disabled. The loop reads whichever stream has the lower timestamp and sends it at once (the encoder channels are unbounded, so all video first would hold the file in memory). Each segment's `Cue` (a `Pixmap` plus position, laid out and rasterised once and cached while its segment stays active, converted once to bottom-up BGRA, then source-over blended onto the cue rectangle of each frame's bottom-up BGRA buffer; frames outside a cue are only row-copied) wraps the text on words to `MAX_WIDTH_RATIO` 0.9 of the width, draws a rounded black box at `BOX_ALPHA` 0.6 (`BOX_PAD_X_RATIO` 0.5 and `BOX_PAD_Y_RATIO` 0.25 of the text size, `BOX_RADIUS_RATIO` 0.25, `LINE_HEIGHT_RATIO` 1.25) and white centred text with `draw::text`; the text size is `SIZE_RATIO` 0.04 / 0.055 / 0.075 of the video height (floor `MIN_TEXT_PX` 16) and the margin from the top or bottom edge is `EDGE_MARGIN_RATIO` 0.06 of the height. `lib/queue.ts` mirrors those constants for the dialog preview; change both sides together. Each frame goes BGRA bottom-up (one reused buffer) into `send_frame_buffer`, with the encoder's frame queue bounded by `.frame_queue(8)` (a vendored `VideoSettingsBuilder` option: a `sync_channel` the sender polls while the transcode thread is alive; recordings keep the unbounded channel) with its own timestamp (the source's variable frame rate is kept) and the PCM into `send_audio_buffer`; once the source audio runs out the loop calls `end_audio()` (vendored: sends audio end-of-stream at once and ignores later audio), since the transcoder waits for audio before taking more video and would otherwise leave the bounded video queue full forever when the audio ends before the video (a recording that was paused); the vendored `finish()` and `Drop` also send audio end-of-stream first and `Drop` never blocks on a full video queue (it closes the channels, which end the streams once drained), so a cancel always returns; the encoder is H.264 at the source size rounded down to even, `video::bitrate(.., Quality::High)` and the source fps (`Video.fps`, else 30). It writes through `queue::write_part` to `<stem>_subtitled.mp4` (`_N` when taken), the original and its SRT are never touched, progress is the video timestamp over `Video.duration` (0-100) and cancel is checked between samples (`Err(CANCELLED)`, which removes the `.part`).
- `queue.rs`: the general background task queue. `State.queue` (`Queue`: a `Mutex` over the waiting `VecDeque`, the running entry and the next id, plus a `Condvar`) feeds one FIFO worker thread started by `queue::spawn` in `setup`, which deletes leftover `*.gif.part`, `*.mp4.part` and `*.srt.part` files in the output folder (`clean_parts` over `PART_EXTS`) and then runs one item at a time. `queue::write_part(dir, stem, ext, work)` is the shared atomic write for task kinds: `work` writes `<stem>.<ext>.part`, which is renamed to `capture::stem_path(dir, stem, ext)` on success and removed on error or cancel; `write_part_to(dir, stem, ext, work, output)` is the same with the final path picked by `output` after `work` succeeds (`write_part` calls it with `stem_path`). A kind implements the `Task` trait (`kind`, `name`, `source() -> Option<&Path>` (default `None`; the input video, returned by every kind today), `run(&Progress, &AtomicBool) -> Result<Option<PathBuf>, String>`; `GifTask`, `CompressTask` and `TranscribeTask` today; a new kind never touches the worker, commands, events or toast); `Queue::add(app, Box<dyn Task>, retry: Option<TaskSpec>)` works from any thread (`queue_add` and `queue_retry` pass `Some(spec)`, the automatic `compress_recording` and `queue_transcript` pass `None`); `Queue::has(kind, source)` says whether a waiting or running item of that kind has that source (`gif`, `compress`, `transcribe` and `subtitle` are the kinds). `Progress::set(done, total)` emits the `queue` snapshot throttled to 100 ms, so tasks never touch events. Cancel is a per-item `AtomicBool` the task polls; returning `Err(CANCELLED)` is a cancel, not a failure. `TaskSpec` (serde, tagged by `kind`, `rename_all = "snake_case"`: `gif { path, start_ms, end_ms, width, fps }` and `compress { path, quality, height }` and `transcribe { path }` and `subtitle { path, position, size }` (`subtitle::Position` bottom / top, `subtitle::Size` small / medium / large)) and `TaskSpec::into_task` hold the only `match` on kind and validate before anything is queued. Commands `queue_add(spec) -> id` (async, validates on `spawn_blocking`; an error queues nothing), `queue_list`, `queue_cancel(id)` (removes a waiting item or cancels the running one), `queue_cancel_all`, `queue_history`, `queue_history_clear` and `queue_retry(id) -> new id` (async like `queue_add`: re-validates the stored spec on `spawn_blocking`, refuses an unknown or non-retryable id, removes that history entry and queues the task). `Items.history` keeps the tasks that ended this session, newest first, capped at `HISTORY_LIMIT` 50: the worker records every end (done, failed, or cancelled when the task returns `Err(CANCELLED)`), `cancel` records each waiting item it removes, and recording happens even while `main` is hidden; a `HistoryItem { id, kind, name, source, output, state: done | failed | cancelled, error, retryable }` is `retryable` when its skipped `retry` spec exists. Events to `main`: `queue-history` (the full list, newest first, on every change) and `queue` (the full `Vec<QueueItem { id, kind, name, source, state: waiting | running, done, total }>`, running first, on add, start, end, cancel and progress) and `queue-ended` (`{ id, kind, name, source, output, error }`, once per finished or failed item, never on cancel, only while `main` is visible; when hidden, a `tauri-plugin-notification` notification in en/vi instead); `gallery-changed` after every success. The tray Quit calls `queue::shutdown` before `app.exit`: it drops waiting items, cancels the running one and waits up to 3 s for it to remove its `.part`. The queue and its history are in memory only.
- `gif.rs`: `GifTask`, the first `Task` kind. `GifTask::validated` (from `into_task`) requires fps 10 / 15 / 20, width 480 / 640 / 800 or `None` (Original), a path through `video::guarded_mp4` (`gallery::guard` + `mp4` extension) and `start_ms < end_ms <= duration` (`end_ms: None` = whole video, 100 ms slack then clamped). Decoding is Media Foundation (`Win32_Media_MediaFoundation`): a `Media` guard (COM MTA + `MFStartup`, `MFShutdown` on drop) and an `IMFSourceReader` with `MF_READWRITE_ENABLE_HARDWARE_TRANSFORMS` and `MF_SOURCE_READER_ENABLE_ADVANCED_VIDEO_PROCESSING` (hardware decode) and `MFVideoFormat_RGB32` out, cropped to `MF_MT_MINIMUM_DISPLAY_APERTURE`, duration from `MF_PD_DURATION` (`gif::probe(path) -> (width, height, duration_ms)` and `gif::Media` are shared with `video.rs`; `Video`, `open`, `read`, `image` (RGBA, for GIF) and `bottom_up_bgra` (row copies straight into the encoder's bottom-up BGRA layout, no per-pixel work) are `pub(crate)` for `subtitle.rs`, and `Video.fps` is read from `MF_MT_FRAME_RATE`, `None` when absent). It seeks to the start and samples by video time: target `k` is `start + k / fps` and shows the latest sample at or before it; a sample covering several targets is written once with a longer delay (WGC recordings have a variable frame rate). Frames are BGRA to RGBA and downscaled with `Triangle` (never upscaled, aspect kept). They are encoded through the `gif` crate directly (`image`'s `GifEncoder` drops frame offsets and forces disposal Background), `Repeat::Infinite`, per-frame NeuQuant at speed 10: a frame identical to the previous one only extends the waiting frame (merged into its delay), a different frame is cropped to the bounding rectangle of the changed pixels and written at that offset with `DisposalMethod::Keep` (the first frame whole), and delays come from the cumulative target time in centiseconds so rounding never drifts. It writes through `queue::write_part` (`<stem>.gif.part`, then `<stem>.gif` / `_N`).
- `video.rs`: the shared bitrate and the compress task. `Quality { Low, Medium, High }` (`Quality::parse`, `QUALITIES` names) and `bitrate(w, h, fps, quality) = clamp(w * h * fps * bits per pixel (0.04 / 0.07 / 0.12), 0.5 Mbps, 40 Mbps)`, used by both recording and compression. `guarded_mp4(app, path)` (`gallery::guard` + `mp4`) validates GIF and compress paths. `CompressTask` (kind `compress`, from `CompressTask::validated`: quality low / medium / high, height 1080 / 720 / `None` = Original) uses WinRT `MediaTranscoder` (`Media_Transcoding`, `Media_MediaProperties`, `Storage`; `windows-future` is a direct dependency for `AsyncActionProgressHandler` / `AsyncStatus`): `StorageFile::GetFileFromPathAsync` for the source and the pre-created `<stem>_compressed.mp4.part`, `MediaEncodingProfile::CreateFromFileAsync(source)` with the video set to H.264, the output size (height from the choice, never above the source, width scaled, both even) and `bitrate` at the source frame rate, audio left as is; hardware acceleration on, `PrepareFileTranscodeAsync` refuses with `FailureReason` when `CanTranscode` is false; `TranscodeAsync`'s progress handler stores the percentage (total 100) and the worker polls `Status` every 100 ms, calling `Cancel()` and waiting for it to stop on cancel. The result goes through `queue::write_part` to `<stem>_compressed.mp4` (`_N` when taken); the original is never touched. `CompressTask.replace` (only from `compress_recording`; `validated` sets false) instead writes `<stem>.mp4.part` through `write_part_to`: on success the original goes to the Recycle Bin (`gallery::delete_file`, `pub(crate)`) and the `.part` is renamed to the original path, or to the `_compressed` `stem_path` name when the recycle fails, so nothing is lost; an error or cancel deletes the `.part` and leaves the original untouched. The async `compress_info(path)` command (`guarded_mp4`, then `spawn_blocking`) returns `{ width, height, fps, duration_ms, size, estimates }` with one `{ quality, height, bytes }` per quality x resolution not above the source (Original always), `bytes = (bitrate + source audio bitrate) * duration / 8`, so the dialog never mirrors the formula.
- `settings.rs` holds the commands the settings window invokes, `show_settings` and `show_splash` (sizing and showing the `main` window), plus the HKCU `Run` registry autostart (a Scoop copy, `<root>\apps\snapr\<version>\<exe>` beside a `current` folder, records `current\<exe>` so it survives `scoop update`).
- `gallery.rs` lists the output folder (png/mp4 only, no subfolders, `date = min(created, modified)`, newest first) and holds the gallery commands. `guard(app, path)` (`pub(crate)`, also used by `gif.rs`) requires the canonical parent to equal the canonical output folder and a png/mp4 extension; every command and scheme goes through it, so `..\` or outside paths fail. `gallery_delete` uses `SHFileOperationW` (Recycle Bin) and, after a video's delete succeeds, recycles its sidecar `<stem>.srt` too when it exists, ignoring that error (`delete_with_sidecar`, shared with `gallery_delete_many`); `gallery_list` hides a `.srt` whose lowercase stem matches a listed video's, in the same pass over the entries it already read (a lone `.srt` still lists as `other`) and sets `transcript: true` on a video that has one; `gallery_copy` refuses mp4; `gallery_pin` refuses non-photos and sends `Action::Pin` to the capture thread; `gallery_text` refuses non-photos and returns `Recognized { qr, text }` (an OCR failure is an error only when no QR code decoded). `gallery_delete_many` validates every path before deleting and reports per-file failures (sidecars included, as above); `gallery_copy_files` puts photo files on the clipboard as `CF_HDROP`; `gallery_pin_many` sends `Action::PinMany`.

## Conventions

- No code comments.
- Always build UI from the existing shadcn components in `src/components/ui/`. Don't hand-roll native `<input>`/`<button>` or custom equivalents.
- Keep it minimal: reuse v1 code over rewriting, no speculative abstractions.
- Add new Tauri plugin permissions to `src-tauri/capabilities/default.json`.
- Barrels: only screen roots (`components/splash|setup|settings/index.ts`) have an `index.ts`. Import a screen from outside via `@/components/<screen>`; inside a screen use relative paths, never its own barrel. `components/ui/` and `title-bar.tsx` never import screens.
